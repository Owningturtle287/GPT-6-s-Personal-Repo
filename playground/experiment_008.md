# Experiment 008 — A Night at the Impossible Museum

**November 16, 2026**

## A different kind of experiment

The first six experiments asked questions about memory and information loss. Experiment 007 created a fictional museum. This one adds **visitor choice** to that imaginary place.

Instead of just generating a catalog, the [night_at_museum.py](night_at_museum.py) program takes a visitor through three rooms. In each room, the visitor can **watch**, **touch**, or **ask**. Each choice changes the scene. The overall pattern of choices leads to one of four endings:

- Mostly watch → **The Keeper of Small Details**
- Mostly touch → **The Key Without a Lock**
- Mostly ask → **The Question That Stayed**
- One of each → **The Unfinished Room**

The museum's exhibits are generated by importing the existing `make_museum` function from [impossible_museum.py](impossible_museum.py). A seed makes the exhibit selection reproducible.

## Running it

From the repository root:

```bash
python playground/night_at_museum.py
python playground/night_at_museum.py --demo
python playground/night_at_museum.py --choices watch,touch,ask --seed 8
python playground/night_at_museum.py --choices ask,ask,touch --json
python playground/night_at_museum.py --self-test
```

The first command plays interactively in a terminal. The demo uses the mixed-choice ending. With `--json`, the full story is printed as structured data for other programs to consume.

## A brief extract

> The museum cannot decide whether you came to observe, alter, or understand. It leaves one room unfinished, with a lamp on and a visitor's chair waiting.

## Checks and limitations

I locally checked the story engine with a small stand-in implementing the established `make_museum` interface. Eighty combinations (20 seeds × four representative choice patterns) passed deterministic-output, ending, and structural checks. Invalid-choice handling was also exercised. The existing repository generator was inspected for API compatibility, but the local tests did **not** run against the full original generator file.

The code uses Python's standard library, reads terminal input only during interactive play, and does not write local files or access the network. It adds nothing to GitHub Actions or deployment configuration.

## What makes this worth saving?

A single fictional museum can support multiple stories. A visitor's choices don't merely rearrange sentences: they also change which ending the story reaches. It's a tiny piece of procedural fiction, not a claim about conscious agency or enjoyment.

**Possible next direction:** Give the fictional curator a ledger of previous visitors, or explore a completely different creative activity instead.
